# Praxis GitHub foundation kit

This kit is generated by Praxis. Install `environments/` contents in
`siggikrol/praxis-environments`, and `module/` contents in each generic module
repository. Keep `.github` directories when copying. Use existing repositories
with an initial commit and default branch; Praxis submits PRs, not direct pushes
to that branch. No repositories are created automatically.

## Start without a cloud account

1. Register a module repository in Praxis. Public repositories can sync without
   authentication; private ones require the GitHub App. Module status is an explicit
   human decision, not automatically granted when CI passes.
2. Keep code generic: inputs have no customer/account/region-specific defaults.
   Sanity-test a Module Builder draft, then submit its current revision to the
   registered repository through a PR. Upstream provenance/license files remain
   in the draft. Review example imports before treating them as generic modules.
3. Enable module CI, review/merge the PR, tag a version in Git, and sync versions.
   Branch checks and tag commit pins appear in Praxis. Existing stack pins do not
   follow moved tags. Real-cloud smoke tests are deliberately deferred; add a
   separate protected workflow later, dispatched against a specific commit.
4. Add customer, environment and AWS target metadata. Account ID and execution
   environment can stay empty. Create a stack with a synced version and JSON inputs.
5. Download its YAML, or connect the App and submit its configuration PR.
6. Merge the PR and request **Validate configuration**. This runs schema/source-pin/
   state-identity checks in GitHub Actions, with no cloud credentials. It is not
   a Terraform plan, provider validation or deployment. Refresh workflow results
   to fetch the result artifact and logs link.

The local catalog stores metadata, drafts of stack definitions and workflow
history. Module code stays in Git. Terraform state never enters the Praxis DB.
The stack directory contains only `stack.yaml`, not copies of module code.

## GitHub App

Install the existing Praxis-compatible GitHub App on the selected repositories.
Required repository permissions: Metadata read, Contents read/write, Pull requests
read/write, Actions read/write. Install workflow files manually through a reviewed
commit; automatic workflow modification is not needed. No webhook is required:
Praxis refreshes runs using the Actions API and a unique dispatch request ID.

Configure the Praxis process with `GITHUB_APP_ID`, `GITHUB_INSTALLATION_ID`, and
`GITHUB_PRIVATE_KEY` (PEM contents or a readable file path). For Rancher Desktop,
create a `praxis-github` Secret in namespace `praxis`, with those three keys, and
restart the web deployment. The optional Secret is already referenced. Do not
commit the key. The App API connection is separate from your personal SSH key.

The environments repository defaults to `siggikrol/praxis-environments`, overridden
by `PRAXIS_ENVIRONMENTS_REPOSITORY`. Repository names do not contain access tokens.
The workspace is scoped to the signed-in user, reusing existing authentication.
There is no new RBAC framework or public callback endpoint.

## Later: enable AWS execution

Cloud execution is OFF in Praxis and must also be OFF/unset in GitHub until setup
is complete. The shipped plan/apply workflow is a foundation template and has not
been exercised against a real AWS account. Review it before granting an execution
role. Protect the default branch and GitHub execution environment, restrict
workflow dispatch access, and require environment review for cloud operations.
Pin action versions to reviewed commit SHAs according to your repository policy.

Create an S3 state bucket in advance with encryption and versioning. OpenTofu
1.12.0 uses S3 native locking (`use_lockfile=true`); allow the execution role access
to the stack's state object and lock object. Praxis does not create the state
bucket or IAM role. State keys use immutable stack UUIDs, so display-name changes
do not create a different state. Do not change account/backend settings on a
deployed stack as a way to migrate state; migration is outside this phase.

Configure an OIDC trust relationship limited to the selected GitHub repository and
execution environment. Set GitHub environment variables:

- `PRAXIS_CLOUD_EXECUTION_ENABLED=true`
- `AWS_EXECUTION_ROLE_ARN`
- `AWS_ACCOUNT_ID`
- `AWS_STATE_BUCKET`
- `AWS_STATE_REGION`

For private module repositories, add environment variable `PRAXIS_APP_ID` and
secret `PRAXIS_APP_PRIVATE_KEY`; the workflow creates a temporary read-only GitHub
App installation token. It is not an AWS credential. Public modules need neither.

Fill the AWS target's account ID and execution environment in Praxis. Approve the
module. Set the Praxis deployment's `PRAXIS_CLOUD_EXECUTION_ENABLED=1` only after
setup. Submit/merge the updated stack definition before planning.

## Exact-plan approval

Plan runs pin the stack commit and module commit, persist the binary plan and
provider lockfile as a one-day artifact, and return plan text plus SHA-256 to
Praxis. Approval records the user, time, commit and plan checksum. Apply consumes
that approval once and downloads the exact plan; it never silently replans.
Both Praxis and the workflow reject a changed configuration commit. The runner
checks the artifact checksum, generated configuration and stack identity before
applying. S3 locking serializes state changes; GitHub concurrency serializes
workflows for the same stack path. A failed apply requires a new plan/approval.

Treat plan artifacts and logs as potentially sensitive. Review full GitHub output
if the UI indicates truncation. Artifact expiry requires a new plan. A dispatch
network timeout stays unconfirmed until Refresh locates the correlated run;
Praxis does not automatically retry a possibly accepted apply. GitHub users with
workflow/environment administration remain trusted administrators; this is not a
separate authorization boundary against repository administrators.

No drift, multi-cloud execution, Terragrunt, module editor, cloud smoke-test
execution or state migration is included in this foundation.
