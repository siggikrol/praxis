GitHub settings

Choose where Praxis submits modules and stack configuration. These settings belong to your signed-in Praxis user.

Use owner/repository. Each module has its own repository, selected when submitting. Changing these defaults does not move existing repositories or modules.

The token is encrypted using the deployment secret and is never displayed again. Keep that secret stable across deployments. Use HTTPS when accessing Praxis beyond this local machine.

Which credential do I need?

Module submission uses the GitHub API to create commits and pull requests. Your local Git SSH key is not used by Praxis.

For a fine-grained token, select the resource owner and module repositories. Grant Contents: read/write and Pull requests: read/write. Add Actions: read/write for workflow status and dispatch. Metadata read is included by GitHub. Organization approval may be required.

Create the module repository in GitHub with a README, or explicitly select “Create a new private repository” during submission. Praxis also enables release PR creation on new repositories, requiring Administration write permission. Creating repositories requires additional repository Administration permission and access to newly created repositories.

Create a fine-grained token in GitHub · GitHub permission reference

For GitHub App mode, configure GITHUB_APP_ID, GITHUB_INSTALLATION_ID and GITHUB_PRIVATE_KEY in the deployment. Selecting App mode does not send the saved personal token.
